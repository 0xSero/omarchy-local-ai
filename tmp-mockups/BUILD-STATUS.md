- Deviations / triage:
  * tokens served counts only the plugin's own gateway requests (acceptance probes): the attested gateway image logs no usage and exposes no stats endpoint, so agent traffic is invisible to the controller. Follow-up belongs in local-ai-images (a usage line per request or a /stats endpoint), then usage_windows reads it.
  * the 4th stats cell is "vram in use" (nvidia-smi on the chosen card) instead of "total KV cache": no engine-agnostic KV figure exists through the gateway.
  * stop is not offered while a download or start is in flight: the controller holds the op lock and `unload` would only be refused; the working surface shows the progress zone and the step. Adding a cancel verb is a controller change outside this brief.
  * port is shown, not picked: there is no port verb, and adding config verbs was out of scope.
  * the card's outer border is the shell's BorderSurface with a flat #2e2e2e line; its corner radius follows the theme's Hyprland rounding (KeyboardPanel does not expose it), which is 0 on the matte theme.
  * omarchy-restart-shell could not kill the running quickshell here (its kill loop times out); SIGTERM to the quickshell pid makes omarchy-launch-shell relaunch it, which is what the test used.
  * the installed plugin dir (~/.config/omarchy/plugins/sero.local-ai, a git clone of main) carries the panel-v5 working tree via rsync so the new panel stays live; `git -C ~/.config/omarchy/plugins/sero.local-ai checkout -- .` restores the main checkout.
